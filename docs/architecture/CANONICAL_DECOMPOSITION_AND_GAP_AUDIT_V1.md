# VAIXLNS Canonical Decomposition + Gap Audit V1

## Rule

Decompose first. Synthesize second. Preserve lineage throughout.

The archive describes a much larger architecture than the executable surface currently
present in VAIXLNS-unified. This document makes that distinction explicit.

## Four-domain room

The primary technical room is:

MATHEMATICS + PHYSICS + ENGINEERING + COMPUTING

It is not four disconnected assistants. They share the same intelligence, invention,
simulation, verification, execution, memory and interface planes.

A mission can activate any subset of the four domains; VX composes only the required
minds and workspaces.

## OpenAI bridge

The repository now exposes an optional Responses API adapter. Current OpenAI documentation
shows client.responses.create and identifies the Responses API as the low-level path when an
application owns its own loop. The adapter therefore sits in the intelligence plane and does
not bypass VX authority.

## GitHub boundary

GitHub remains the source-control and engineering federation layer. Source-owned repositories
should remain separately identifiable; the canonical registry records their roles, lineage and
integration status rather than silently copying all source trees.

## Research-backed integration principles

- OpenAI agent tooling provides tools, MCP, sandboxes, guardrails and tracing; VX should use
  these as integration primitives rather than treating an LLM as authority.
- MCP should be integrated with explicit trust, least-privilege and approval boundaries.
- Kubernetes reconciliation is a useful operational pattern for continuously driving actual
  state toward declared desired state.
- OpenTelemetry provides vendor-neutral traces, metrics and logs.
- SLSA provenance provides a model for tracing artifacts to their sources and build process.
- NVIDIA Omniverse/OpenUSD provides an ecosystem for physical-AI simulation and digital twins.

These are integration references, not assertions that VAIXLNS already implements each one.
