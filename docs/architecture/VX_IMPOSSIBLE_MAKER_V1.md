# VX Impossible-Maker V1

## Mission
VX is a selectable multi-domain problem-solving and invention runtime. A customer chooses a mission, domain, autonomy level, and desired output; VX composes the required agents, models, interfaces, memories, simulations, tools and repositories.

## Domains
- Mathematics / formal reasoning
- Physics / simulation
- Engineering / CAD-like system reasoning
- Computing / software / algorithms
- Systems architecture
- Research / discovery
- Optimization
- Security / validation
- Operations / recovery
- Cross-domain invention

## Core loop
SELECT MISSION -> DECOMPOSE -> ROUTE MINDS -> SEARCH KNOWLEDGE -> SYNTHESIZE -> SIMULATE -> TEST -> VERIFY -> EXECUTE -> RECORD -> LEARN -> COMPOSE NEW CAPABILITY

## Invention-native primitives
1. Agent as an invention: a reusable problem-solving capability with identity, contract, evidence and lineage.
2. Interface as an invention: a task-specific workspace generated from the selected mission.
3. Model as an invention: a model may be composed into a larger model/solver pipeline.
4. Memory as an invention: memories are typed, provenance-aware, reusable and eligible for controlled evolution.
5. Workflow as an invention: successful workflows become reusable capabilities.
6. Repository as an invention source: GitHub code and documentation become discoverable engineering material, subject to provenance and verification.
7. Simulation as an invention gate: candidates can be tested before promotion.

## Authority boundary
Intelligence produces proposals. Policy/authority decides what may execute. VX executes. VV/OIF verify and produce evidence/proof.

## Customer-selectable modes
- Solve: maximize decomposition and verification.
- Build: generate implementation artifacts.
- Simulate: prioritize mathematical/physical models.
- Engineer: prioritize architecture, constraints and trade-offs.
- Discover: search repositories/knowledge for reusable capabilities.
- Invent: generate and test new compositions.
- Operate: run, observe, recover and maintain.
- Research: produce evidence-backed hypotheses and experiments.

## Memory Fabric
Memory is not a chat transcript. Each memory item carries: id, type, source, provenance, confidence, scope, dependencies, evidence, validity window, lineage, reuse permissions and evolution status.

## Color semantics for the interface
- Graphite: system/control plane
- Electric cyan: computation/data flow
- Violet: intelligence/multi-mind
- Amber: innovation/candidate
- Green: verified/operational
- Red: blocked/failure/security gate
- White: neutral workspace

These colors are semantic UI tokens, not claims of technical superiority.

## Definition of done
A capability is promoted only when it has an owner, contract, tests, evidence, reproducible execution path, and lineage. An invention remains a candidate until verification gates pass.
