# VXSL — System Language V1

## Core idea
VXSL is the semantic language above implementation languages.
The source of truth is a canonical system model: domains + quantities + laws + states + constraints + capabilities + minds + simulations + proofs + interfaces + ownership + lineage.
Implementation code becomes a compiled projection rather than the semantic source of truth.

## Four-domain room
MATHEMATICS + PHYSICS + ENGINEERING + COMPUTING share intelligence, invention, simulation, verification, authority, execution, memory and interface.

## Domain roles
Mathematics: symbolic expressions, quantities, optimization, invariants and proof obligations.
Physics: differential/algebraic laws, units, events, dynamics and simulation.
Engineering: topology, components, constraints, resources and reliability.
Computing: algorithms, concurrency, resource bounds, execution and recovery.

## Polyglot lowering
Lean -> formal proof
Modelica + FMI -> dynamic multi-domain models and co-simulation
Julia + Python -> numerical/scientific computation and orchestration
Rust + C++/CUDA -> runtime and accelerated kernels
WebAssembly -> portable sandboxed artifacts
TypeScript -> mission interfaces
OpenUSD -> digital-twin / scene representation
SQL + Arrow -> persistent data and interchange

The VXSL graph and canonical IR remain above all of them.

## Law lifecycle
INGEST -> NORMALIZE -> PROVENANCE -> VALIDATE -> VERIFY -> PROMOTE
A conversational answer is evidence input, not automatically a system law.
Authorized model outputs may enter LawBook with source, provenance, validation backend and status.

## Intelligence trait lifecycle
OBSERVE -> BENCHMARK -> SCORE -> REGISTER -> COMPOSE -> CROSS-CHECK -> EVOLVE
VX can compose a mission-specific mind from measured traits without copying another model's weights.

## Visual engineering lifecycle
SYSTEM -> EQUATIONS -> SIMULATION -> DIAGRAMS -> KEYFRAMES -> NARRATION -> VIDEO -> EVIDENCE OVERLAY -> REVIEW -> ARCHIVE

## Project sovereignty
Customer projects remain customer-owned.
Reserved identities: GOLDEN_WALLET / المحفظة الذهبية and BEAST / الوحش.
Agents receive bounded permissions; they do not acquire project ownership.

## Design objective
One system description should be able to compile into many verified runtime and media projections without making any one implementation language the semantic authority.
